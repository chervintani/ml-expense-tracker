# Smart Expense Tracker with AI Categorization

A full-stack expense tracker where a **PHP/Laravel** backend delegates text
classification to a dedicated **Python/TensorFlow** machine-learning
microservice. Log an expense (description + amount) and the system predicts its
category, returns a confidence score, flags statistical outliers, and lets the
user confirm or correct the prediction.

> Built as a portfolio piece to demonstrate PHP, JavaScript, a real ML model
> (TensorFlow/Keras), MySQL, REST API design, and multi-service architecture.

---

## Architecture

```
          ┌─────────────────────────────┐
          │  Frontend (HTML + vanilla JS)│
          │  form • table • dashboard     │
          └──────────────┬──────────────┘
                         │  REST (JSON / HTTP), same origin
                         ▼
          ┌─────────────────────────────┐        ┌──────────────────────┐
          │  Backend — PHP / Laravel     │◄──────►│  MySQL database      │
          │  Controllers → Services      │  SQL   │  categories          │
          │  outlier detection           │        │  expenses            │
          │  graceful ML fallback        │        │  prediction_logs     │
          └──────────────┬──────────────┘        └──────────────────────┘
                         │  REST (JSON / HTTP)
                         ▼
          ┌─────────────────────────────┐
          │  ML microservice — Flask     │
          │  TF-IDF + Keras dense net    │
          │  POST /predict (stateless)   │
          └─────────────────────────────┘
```

**Why this shape?** ML inference lives in a single-purpose Python service
instead of being reimplemented in PHP. The Laravel backend owns the database and
business rules and calls the model over HTTP — the same separation-of-concerns
pattern real PHP/Python hybrid shops use. The ML service is stateless: it loads
the model once at startup and never touches the database.

## Features

- **Add an expense** (description + amount) through a clean web form.
- **Automatic categorization** into Food, Transport, Utilities, Shopping,
  Bills, or Other, with a **confidence score** from the model.
- **Confirm / correct** a prediction in the UI — sets the row to `confirmed`
  and feeds the trusted baseline for outlier detection (human-in-the-loop).
- **Outlier detection** — an expense is flagged when its amount exceeds
  `mean + 2·stddev` for its category (needs ≥ 5 prior samples; explainable, no
  extra model).
- **Dashboard summary** — total spend per category and a count of flagged
  outliers.
- **Soft delete** — removing an expense keeps the record (and its prediction
  log) in the database.
- **Prediction logging** — every ML response is stored in `prediction_logs`
  with latency and model version for debugging / future evaluation.
- **Graceful degradation** — if the ML service is unreachable, the expense is
  still saved and marked `Uncategorized` instead of failing the request.

## API

| Method  | Endpoint                       | Description                                  |
|---------|--------------------------------|----------------------------------------------|
| GET     | `/api/expenses`                | List expenses (paginated, 20/page)           |
| POST    | `/api/expenses`                | Create expense → predict → outlier-check     |
| GET     | `/api/expenses/{id}`           | Get a single expense                         |
| PATCH   | `/api/expenses/{id}/confirm`   | Confirm/correct the category (→ `confirmed`) |
| DELETE  | `/api/expenses/{id}`           | Soft-delete an expense                       |
| GET     | `/api/categories`              | List categories                             |
| GET     | `/api/dashboard/summary`       | Totals per category + outlier count          |
| GET     | `/api/health`                  | Combined API + ML service status             |

**Create an expense**

```bash
curl -X POST http://localhost:8000/api/expenses \
  -H "Content-Type: application/json" \
  -d '{"description":"Grab to office","amount":180}'
```

```json
{
  "id": 1,
  "description": "Grab to office",
  "amount": "180.00",
  "predicted_category": "Transport",
  "prediction_confidence": 0.99,
  "is_outlier": false,
  "outlier_reason": null,
  "status": "predicted",
  "created_at": "2026-06-20T12:00:00.000000Z"
}
```

**ML service (called by the backend, not the browser)**

```bash
curl -X POST http://localhost:5001/predict \
  -H "Content-Type: application/json" \
  -d '{"description":"Jollibee lunch"}'
```
```json
{
  "category": "Food",
  "confidence": 0.91,
  "all_probs": { "Food": 0.91, "Transport": 0.02, "...": 0.0 },
  "latency_ms": 24,
  "model_version": "1.0"
}
```

## Database

Three tables (see `backend/database/migrations`):

- **categories** — `id`, `name` (seeded with the 6 categories).
- **expenses** — `description`, `amount`, `category_id`, `predicted_category`,
  `prediction_confidence`, `is_outlier`, `outlier_reason`,
  `status` (`pending` → `predicted` → `confirmed`), timestamps, soft-delete.
- **prediction_logs** — full ML response per expense (`raw_input`,
  `raw_response` JSON, `model_version`, `latency_ms`) for debugging/evaluation.

## The ML model

- **Data** — ~215 labeled rows generated by `generate_data.py` from realistic
  Philippine-context vendor/item templates (Grab, Jollibee, Meralco, Shopee…).
- **Features** — `TfidfVectorizer` with unigrams + bigrams (top 500 features).
  TF-IDF is a strong, cheap fit here: category words ("grab", "meralco",
  "netflix") are highly distinctive, so a heavyweight embedding/LLM is overkill.
- **Model** — a small Keras `Sequential`: `Dense(128) → Dropout → Dense(64) →
  Dense(6, softmax)`, trained with categorical cross-entropy.
- **Artifacts** — `expense_classifier.h5`, `vectorizer.pkl`, `label_encoder.pkl`,
  all loaded once when the Flask service boots.

Retrain anytime with `python train.py` after editing the dataset.

## Running locally

Three processes: **MySQL**, the **Flask ML service** (port 5001), and the
**Laravel app** (port 8000, which also serves the frontend). Or just run
`bash start.sh` from the project root to launch all three.

### 1. ML microservice

```bash
cd ml-service
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python generate_data.py        # writes data/expenses.csv (optional; committed)
python train.py                # writes model/expense_classifier.h5 + .pkl files
python app.py                  # serves http://localhost:5001
```

### 2. Database + backend

```bash
brew services start mysql
mysql -u root -e "CREATE DATABASE IF NOT EXISTS expense_tracker;"

cd backend
composer install
cp .env.example .env            # already configured for MySQL / expense_tracker
php artisan key:generate
php artisan migrate --seed      # creates tables + seeds the 6 categories
php artisan serve               # serves http://localhost:8000
```

### 3. Open the app

Visit **http://localhost:8000** — the frontend is served by Laravel from
`public/`, so there are no CORS concerns.

To populate the app with sample data (including one outlier) for a quick demo:

```bash
bash scripts/demo-data.sh
```

> **Note:** the ML service runs on port **5001**, not 5000 — on macOS port 5000
> is taken by the AirPlay Receiver. The project uses a Python **3.12** venv
> because TensorFlow has no wheels yet for the newest Python releases.

## What I'd do with more time

- More (and real) training data; swap TF-IDF for learned embeddings.
- A feedback loop: confirmed categories feed back into a retraining pipeline.
- A proper anomaly-detection model (e.g. Isolation Forest) instead of the
  mean/stddev rule.
- User accounts and authentication.
- Receipt image upload → OCR (Tesseract) → feed text into the same classifier.
- Containerize the three services (Docker Compose) and deploy.
- Move ML prediction to a queue so it doesn't block the API response.
